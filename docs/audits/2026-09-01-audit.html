Platform features you already pay for and never call

Verified across the whole repository — zero matches for shouldRevalidate, clientLoader, prefetch, <Await> or Suspense. No route defines shouldRevalidate, so every navigation re-runs every matched loader. No <Link prefetch="intent"> exists anywhere; on an SSR React Router app that single attribute typically removes most perceived navigation lag, because the loader runs on hover rather than on click.

Two further costs: /recruiter-search revalidates every 400 ms while a run is active (recruiter-research-page.tsx:133-139) at 5+ SQLite reads a tick, and api/discovery-runs performs an UPDATE write on a GET (discovery-runs.ts:32,45).

On “are we missing core libraries”: no, and buying one would be the wrong move. A client query cache such as TanStack Query duplicates React Router's own loader revalidation model and would add weight to a JS budget that is currently 594 bytes over. The wins here are two deleted columns, one denormalised count, shouldRevalidate, and prefetch="intent" — all free.

Stream 04

Design system: well built, and structurally outranked by the cascade

HighUI-013,469 lines of product CSS sit outside the layer cascade and beat the entire design system

Evidence design-ui/styles.css:3 declares the order:

@layer job-radar.tokens, job-radar.reset, job-radar.components, job-radar.product;

But discovery/…/styles.css opens a single @layer job-radar.reset block at line 3 that closes at line 71 — lines 73–2472 are unlayered. And recruiter-engagement/…/styles.css contains no @layer at all; all 997 lines are unlayered.

The declared job-radar.product layer is never opened by anything. Per CSS Cascade Level 5, unlayered declarations sit in an implicit final layer that beats every named layer regardless of specificity. Concretely: .utility-control (styles.css:221, specificity 0,1,0, unlayered) defeats .jr-button[data-variant="secondary"] (design-ui/styles.css:57, specificity 0,2,0, layered) and imposes border: 0, width: 68px, min-height: 68px on a design-system Button.

The design system cannot win an argument it is not allowed to enter. This is the root cause of five field-label treatments, three parallel section-header implementations sitting 2–6 px apart, 22 raw <input> elements that never touch TextField, and 16 page-level selectors reaching into .jr-* internals. The drift is structural, not a discipline failure.

Fix Wrap both product stylesheets in @layer job-radar.product { }. This is not a two-line change and must not be sequenced as one. Wrapping fixes design-system-versus-product conflicts only; it does not reorder anything within the product sheet, so intra-product conflicts survive untouched. And 13 rules that currently win will start losing and must be converted to named component variants first — styles.css:391, 773, 898, 902, 921, 925, 935, 939 and five others. @keyframes are exempt from layer ordering, so moving them is safe. Sequence: capture visual baselines → convert the 13 → wrap. Effort M–L

Section 08

What is already good, and must not be rebuilt

An audit that recommends replacing working machinery is worse than no audit. This repository is above the norm on several axes and the remediation below deliberately preserves all of it.

  • The hexagon is real. Zero layer violations across 368 files. ~40 ports each owned by their innermost consumer. Ten cross-context imports, all through declared public contracts.
  • Type safety is near-perfect. Zero escape hatches of any kind, under four strict compiler flags.
  • The ubiquitous language is exceptional. Two CONTEXT.md files with canonical terms and explicit _Avoid_ aliases. Most teams never get this far.
  • The e2e journeys that exist are real. Real built server, real SQLite, real HTTP. The zero-match funnel and shortlist specs are genuinely excellent.
  • Theming is correct. All light/dark variance confined to the token layer, with machine-tested contrast.
  • Motion tokens are correct, including prefers-reduced-motion zeroing all four durations.
  • CI is well built. Eleven checks, SHA-pinned actions, a 3-OS clean-start matrix, actionlint, a workflow-policy script, and private artifact upload.
  • Dependency selection is disciplined. Off-the-shelf reference data, direct library use, no speculative wrappers.
  • Nine architecture tests that demonstrably work — which is exactly why the rules they cover have not drifted.
Section 09

Remediation, in dependency order

The order matters. Steps 1–3 restore sight; nothing later can be trusted until they land. Step 4 must precede step 6, because you cannot safely make the cascade change without baselines.

1

Get CI green and stop one failure blinding five gates

Fix the 594-byte overage by reducing, not by raising the limit — start with PERF-01, which removes payload from the client. Then split verify into independent jobs (or add if: always() to the independent steps) so a size overage can never again hide the e2e and performance suites. Separately, cut the 3-OS clean-start matrix to Linux on push and reserve macOS/Windows for a release tag: at 10×/2× billing it is consuming the minutes that the gates you actually need are then denied.

Unblocks: navigation budget · Lighthouse · Web Vitals · the entire Playwright suite · both scheduled workflows
2

Make the local gate resemble CI, since the remote gate cannot exist

Branch protection needs GitHub Pro ($4/mo — the highest-return spend available to this project). Until then, pre-push is your only enforcement. Expand it beyond typecheck + test to include lint and build, and scope the expensive checks by changed path. Keep it under about 90 seconds; a pre-push that takes six minutes gets bypassed with --no-verify and is not a gate.

Also: a red-main alarm, because the failure mode is not silence, it is nobody acting on red
3

Make the performance fixture representative

Seed realistic description and raw_payload sizes and realistic excluded-match counts in seed-performance-database.ts. The navigation budget then measures your app instead of a 1,372×-lighter fiction — and will immediately fail, which is the point.

4

Turn 54 screenshots into 54 assertions

Convert page.screenshot() to toHaveScreenshot(), commit Linux-only baselines, and set a small maxDiffPixelRatio. This is the single highest-value change for “things are out of line when I log in”, and the capture work is already done.

5

Fix the performance root causes

PERF-01 (delete two columns), PERF-02 (incremental counts), shouldRevalidate on the settings tree, prefetch="intent" on primary nav links, back off the 400 ms recruiter poll, and move the UPDATE off the GET.

6

Close the cascade and fix the scale

Convert the 13 rules that currently override design-system components into named public variants, then wrap both product stylesheets in @layer job-radar.product. Then raise the type scale (retire micro, move body to 14–15px), build a real elevation scale to replace border-carried structure, and add a large radius step. Load the product CSS into the Storybook preview so stories show what ships.

Requires step 4 first · highest blast radius in the audit · the wrap alone does not fix intra-product conflicts
7

Write the four missing daily-loop journeys

Mark applied, hide/restore, filter the list, opportunity counts. Extend the existing specs rather than adding new files. Start with a failing test for job-filters.tsx.

8

Convert declarations into checks

Extend context-boundaries.test.ts to cover adapter selection outside composition, product policy in src/platform, and bare package specifiers in presentation. Add a stylelint config that fails unlayered product CSS and page-level .jr-* overrides. Add the _Avoid_ vocabulary check that parses both CONTEXT.md Language sections. Widen the coverage include and the Stryker mutate scope. Add minimumReleaseAge, knip, and pnpm audit to CI.

9

Rewrite AGENTS.md down to what is checkable

349 lines, roughly a third unenforceable as written, declaring a five-command gate that does not match CI and includes one command that cannot run in CI. Cut it to the rules a machine enforces plus the few judgement calls that genuinely need prose, and point the rest at the checks. Then create retrospectives/RETROSPECTIVE.md, which the rulebook has mandated since day one and which has never been written here.

Section 10

Housekeeping and method

Immediate housekeeping

Six git worktrees are registered inside the repository at .worktrees/adm-179 … adm-218, all on unmerged branches, including feat/adm-202-navigation-performance — abandoned work on the exact lag you reported. Your global rule places worktrees at /home/ubuntu/code/worktrees/ and requires whoever creates one to remove it. Neither happened, and the rule lives in global CLAUDE.md where this repo's tooling never reads it. A stale worktree survives a reboot as a registration whose files are gone, at which point the repository reports every file in it as deleted.

Method

Six read-only streams ran in parallel — UI/design system, performance, architecture, dependencies, testing, process — each required to cite path:line evidence it had personally opened, and to re-verify each finding against an innocent explanation before reporting. Nothing was modified. .worktrees/, node_modules/, build output and generated artifacts were excluded from analysis.

Every Critical and High finding in this report was independently spot-checked by the lead before publication. Five claims were corrected in that pass: an initial reading that the performance gates were unbuilt (they exist, are correctly wired, and would gate every PR if CI reached them); a raw grep of 468 vocabulary hits (most are legitimate canonical terms, so the finding was narrowed to the page and route modules); a font-size count sourced from token definitions rather than product CSS; a CI failure tally that conflated 18 never-started runs with 25 real failures; and an initial description of the @layer remediation as a two-line change, when 13 component overrides must be converted to named variants first. One stream's supply-chain severity was revised down after verification.

Two streams partly refuted the brief they were given, and those refutations are load-bearing: the architecture is sound and should not be restructured, and the existing tests are well written rather than superficial. An audit that only confirmed the commissioner's priors would not have been worth running.

Limits

No build, test suite or browser run was executed against the working tree, to avoid disturbing the running instance and the 1.14 GB private database. Bundle attribution for the 594-byte overage was still in flight at publication. Commit-hook bypasses (--no-verify) leave no trace and could not be assessed.
